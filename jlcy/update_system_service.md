# jlcy 系统服务升级计划

> jlcy 是 JLOS 的用户态运行时：C 标准库（libc）+ 用户态程序运行时基础设施，通过 syscall ABI 与内核交互。
> 本文档定义 jlcy 的整体架构、子系统划分、与内核的接触面，以及升级路线。
> 设计目标与内核一致：**生产级、多架构（x86/ARM/RISC-V）、多核**，不以当前实现规模为约束。

***

## 1. 定位与范围

| 层 | 职责 | 归属 |
|----|------|------|
| 内核 | 硬件抽象、进程调度、内存管理、文件系统、网络协议栈、syscall 服务 | JohnBeauty OS |
| libc | C 标准库、syscall 封装、进程入口（crt0）、动态链接器（未来） | jlcy |
| 系统服务 | init、shell、守护进程（NTP/DHCP/DNS）、系统工具 | jlcy（构建于 libc 之上） |
| 内核测试 | 验证内核 syscall 行为的程序 | jlcy（独立于 libc 与系统服务） |

核心原则：**libc 是库，不是程序**。库提供可复用接口，不承载业务逻辑；业务逻辑（守护进程循环、服务编排）属于系统服务层。

***

## 2. 整体架构分层

jlcy 按「架构无关 / 架构相关」与「接口 / 实现」两个维度分层，与内核的 HAL/arch 分层对齐。

### 2.1 libc 分层

1. **公共头文件**：导出给用户程序的类型、常量、函数原型、syscall 编号镜像、数据结构契约（`timeval`/`timespec`/`mmap_arg` 等与内核共享布局）。属于 ABI，变更需与内核同步。
2. **通用实现**：纯 C 算法，一次编写、多架构复用。字符串、格式化、排序、堆管理等属于此层。
3. **架构相关实现**：进程入口（crt0）、syscall 陷入指令、`setjmp`/`longjmp`、原子原语。每架构一份，编译期绑定。
4. **内部头文件**：仅供 libc 实现内部使用，不对外导出。

### 2.2 架构相关实现的内容

| 项 | 说明 |
|----|------|
| 进程入口 crt0 | 栈初始化 → 调用 main → exit syscall；per-arch |
| syscall 陷入 | x86 `int 0x80` / ARM `svc` / RISC-V `ecall`；参数寄存器约定 per-arch |
| setjmp/longjmp | 保存/恢复 callee-saved 寄存器与栈指针；per-arch |
| 原子原语 | 用户态原子操作；per-arch |

通用实现只调用架构相关实现暴露的接口，不直接写架构专属指令。

### 2.3 三类程序的关系

| 类别 | 链接 libc | 性质 | 说明 |
|------|-----------|------|------|
| 系统服务 | 是 | 常驻/交互程序 | shell、守护进程，实现系统功能 |
| 内核测试 | 是 | 一次性验证程序 | 验证内核 syscall 行为，用完退出 |
| 系统工具 | 是 | 短命命令 | ls/cat 等，类比 POSIX 工具集 |

三者都链接同一个 libc；区分在于职责，而非链接方式。

## 3. 与内核的接触面

jlcy 与内核之间存在四个契约，任何一方的变更都可能破坏另一侧，必须同步维护。

### 3.1 syscall ABI

- **编号**：内核侧定义，jlcy 侧镜像保存，编号必须一致。
- **参数约定**：寄存器（x86 `int 0x80` + eax/ebx/ecx/edx）与参数序列，per-arch。
- **返回约定**：返回值与 errno 错误码语义，负数表示 `-errno`。
- **扩展规则**：新增 syscall 须两侧同步追加编号，禁止单侧修改。

### 3.2 数据结构契约

跨内核/用户态传递的结构体（`timeval`、`timespec`、`mmap_arg`、`stat`、`dirent`、`sockaddr` 等）布局必须两侧一致。定义收敛到一处，内核侧与 jlcy 侧共享同一份字节布局。

### 3.3 内存布局契约

- 用户地址空间布局：ELF 加载基址、brk 堆、用户栈顶、mmap 区域、内核空间边界。
- 内核 mm 子系统按此布局创建 VMA；jlcy 的链接脚本与 crt0 按此布局假设栈/堆位置。

### 3.4 进程模型契约

- fork 语义（子进程返回值、地址空间复制规则）、exit 状态传递、wait_pid 回收、信号递送（handler 地址、sigreturn 流程）。
- libc 的 crt0 与信号封装依赖这些语义。

## 4. libc 子系统规划

按功能域划分，每个子系统是独立的接口 + 实现单元，可独立演进。

| 子系统 | 职责 | 依赖的 syscall |
|--------|------|----------------|
| 基础类型与内存 | types/stddef/string、memcpy/memset/strcmp 等纯 C 实现 | 无 |
| 动态内存 | malloc/free/calloc，基于 brk 的堆管理，多核需线程安全 | brk、mmap |
| 格式化 I/O | printf/sprintf/snprintf、FILE 流缓冲 | write、read |
| 进程与线程 | fork/execve/wait_pid、clone/pthread、线程本地存储 | fork、execve、clone、wait_pid |
| 时间 | gettimeofday/settimeofday、clock_gettime/clock_settime、sleep | 时间 syscall |
| 信号 | signal/sigaction/kill/sigprocmask、信号帧 | signal、kill、sigreturn |
| 文件与目录 | open/read/write/lseek/close、readdir、stat | 文件 syscall |
| 套接字与网络 | socket/bind/connect/send/recv、地址解析 | socket syscall |

每个子系统：公共接口在头文件，实现分通用层与架构相关层；多核安全通过原子原语与线程本地存储实现，接口设计预留线程语义。

***

## 5. 系统服务层规划

构建在 libc 之上的用户态程序，实现系统级功能。

| 服务 | 职责 | 定位 |
|------|------|------|
| init | PID 1，进程生命周期管理、服务编排 | 系统服务核心 |
| 服务管理框架 | 服务注册、启动顺序、依赖、重启策略 | 支撑守护进程 |
| shell | 命令行解释器，进程控制 | 交互核心 |
| NTP 客户端 | 网络时间同步，设置系统时间 | 守护进程 |
| DHCP 客户端 | 自动获取网络配置 | 守护进程 |
| DNS 解析器 | 域名 → IP 解析 | 库 + 守护进程 |

系统服务演进是独立工程，依赖 libc 与内核能力就绪（尤其套接字 syscall）。设计上按「init → 服务管理 → 具体守护进程」的顺序递进。

***

## 6. 升级路线

按依赖顺序，每个阶段独立可回滚。

| 阶段 | 内容 | 依赖 | 目标 |
|------|------|------|------|
| L1 | libc 补全：字符串、格式化 I/O、动态内存、时间、文件、套接字封装 | 无 | libc 覆盖 C 标准库核心 |
| L2 | 进程模型完善：线程、信号、线程本地存储 | L1 | 支撑多线程服务 |
| L3 | init + 服务管理框架 | L2 | 系统服务编排就绪 |
| L4 | 网络守护进程（DHCP/DNS/NTP） | L2 + 内核 socket syscall | 系统网络能力 |
| L5 | 动态链接器 ld.so + ELF 共享库 | L1 | 库复用，替代静态链接 |

> 内核侧前置依赖：套接字 syscall（L4）、完整信号/线程 syscall（L2）。jlcy 升级与内核 syscall 完善同步推进。

***

## 7. 内核测试的定位

内核测试是**独立的一类程序**，与 libc、系统服务并列：

- **职责**：验证内核 syscall 行为（参数校验、返回值、边界、错误路径），用完即退。
- **性质**：一次性验证程序，非常驻、非系统功能。
- **不混入 libc**：libc 是库，测试是程序；测试不进入 libc 的导出接口。
- **不混入系统服务**：系统服务实现功能，测试验证正确性。

测试用例按被验证的内核子系统组织（进程、内存、文件、信号、时间、网络），与内核子系统一一对应，便于定位回归。
